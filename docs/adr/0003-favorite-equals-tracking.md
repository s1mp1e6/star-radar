# ADR-0003：收藏即追踪——只追踪收藏的项目

- **日期**：2026-08
- **状态**：已接受（待用户最终确认）

## 背景

抓取的项目会持续更新（涨星、发 release），需要回答"追踪哪些项目"。
追踪全部项目 = 数据无界（25 项/天 × 无限期），D1 与 API 消耗线性膨胀。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 追踪全部历史项目 | 无遗漏 | 数据无界，D1/GraphQL 消耗失控 |
| 追踪近 N 天项目 | 折中 | 语义复杂，用户无法控制 |
| **收藏 = 追踪** | 语义清晰、量级可控（≤数百）、零新增 UI | 用户想追踪必须收藏 |

## 决策

收藏即追踪。每日 21:00 用 GitHub GraphQL 单请求拉全部收藏仓库最新数据，
写 `star_history` 时间序列（每仓库每天 1 行），收藏页展示涨幅与星标曲线、新 release 徽章。

## 后果

- `star_history` 按 repo+date 主键，天然支持未来"追踪非收藏仓库"（插入即可）
- 收藏量 ≤ 数百时 GraphQL 单请求即可覆盖；若未来超量，按 100 条分片（预留）
- 通知推送（邮件/Webhook）延后到 L2，数据层已就绪
